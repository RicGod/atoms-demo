一、实现思路与关键取舍

本 Demo 的目标不是复刻完整 Atoms，而是在有限时间内打通笔试要求的最小闭环：一句话需求 → 模型生成单文件 HTML → iframe 可交互预览 →（登录后）按邮箱持久化、对话迭代，并支持线性版本回看/回滚与本机导出。

技术选型
• 前端：Vite + React，工作区「左对话 / 右预览·代码」，贴近 Atoms 使用心智。
• 后端：Express 同仓托管 /api 与静态资源，便于 Render 单服务部署。
• 模型：服务端内置百炼 OpenAI 兼容口（交卷主路径）；登录用户另支持本机 BYOK，以及平台默认 qwen3.8-flash（不可删改）。
• 持久化：Turso（libSQL），按邮箱隔离 Task（项目）；成功生成后同一次写入当前 Artifact、线性 Version 快照与对话时间线。
• 交付：Render 公网链接 + public GitHub，密钥只走环境变量，不进仓库。

关键取舍（主动砍掉 / 刻意做浅的）
1. 产物形态限制为「单文件 HTML」：降低生成与预览复杂度，保证打开就能点；不做真多文件工程 / 文件树 / AST 补丁。
2. 版本做「线性快照」而不是 Git 式分支树：每轮成功生成追加 Version（完整 HTML + 改动短摘要）；可回滚 Current、可导出当前版；上限约 20 份。不做分支合并、不做永久无限历史。
3. 赛马：能力保留、入口默认隐藏：避免演示时额度被多路放大；Winner 由人选择，不做 Score 自动裁判。
4. 身份极简：邮箱登记即可，不做 OIDC / 验证码。
5. 额度与稳定性优先：访客可用预置示例 / mock 兜底；失败显式报错进对话，禁止失败却静默换成无关演示页。

整体原则：链接先活、闭环先通、持久化先稳；对话迭代 + 可回看版本做深，少做半成品。

二、当前完成程度

已完成
• 访客：一句话生成 / 预置演示 → 流式思考与代码 → iframe 预览；工作区提示与首页对齐（「当前为访客模式，登录后解锁更多功能」）；返回首页可再进入刚才的预览（会话内存）；可导出当次 HTML。
• 登录：邮箱登记 → 项目列表（新建 / 打开 / 删除）；退出登录清空工作区，避免对话泄漏到访客首页。
• 项目内：多轮对话迭代；迭代时可对照 diff；成功后自动保存 HTML + 对话 + Version 快照。
• 版本管理：代码页可浏览历史版本源码；显式「回滚到此版本」；回滚后对话追加系统说明；再生成线性追加新版本。
• 版本卡文案：版本 N · {模型改动短摘要}（另打一枪短摘要；失败回退 Prompt 截断）。
• 导出：代码页一键下载当前版本（如 标题-vN.html）。
• 模型：平台默认 qwen3.8-flash；可添加自配模型；错误气泡落在对话流内。
• 工程与交付：Render、Turso、health、README / OpenSpec / 测试基线；仓库 public，密钥不入库。

未完成 / 明确不做

• OIDC / 注册验证码
• Git 式分支版本树 / 无限历史
• Score / 自动打分择优
• 真多文件工程与 AST 级补丁
• 访客赛马（登录赛马入口当前也默认隐藏）

三、若继续投入时间：扩展方向与优先级

P0｜恢复并打磨「赛马择优」演示入口（人择 Winner、路数=2）：最贴近 Atoms 招牌能力；需配额度提示与失败兜底。
P0｜迭代体验再加强：失败一键重试、摘要更稳：直接提升可用观感与稳定性。
P1｜项目列表：收藏筛选、最近打开、标题/封面摘要：强化基本使用流程与工程完整度。
P2｜可选只读分享链接（有过期与权限）：有产品延展，但安全成本高，排在赛马之后。
P2｜真多文件或组件化生成：冲击力大，但失败率与评测成本显著升高。

判断标准：先补齐评委一眼能感知的亮点与稳定性（赛马可见化、失败可恢复），再做列表与分享；涉及权限/多文件的能力最后做，避免再次牺牲「链接活着 + 闭环跑通」。
